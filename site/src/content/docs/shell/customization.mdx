# Customization

The Jitzu shell supports theme customization, startup configuration, aliases, and path labels
to personalize your workflow.

## Theme Configuration

Colors are controlled by `~/.jitzu/colours.json`.
A default configuration is written automatically on first launch. All values are hex color strings (e.g. `#87af87`).

### Color Categories

- **syntax** — live input highlighting (commands, keywords, strings, flags, pipes, booleans)
- **git** — prompt git status indicators (branch, dirty, staged, untracked, remote ahead/behind)
- **prompt** — prompt elements (directory, arrow, error state, user, duration, clock, job count)
- **ls** — file listing colors by type (directories, executables, archives, media, code, config, project files)
- **prediction** — history prediction ghost text and dropdown selection
- **selection** — text selection highlight
- **dropdown** — completion dropdown gutter and status bar

Edit any value and restart the shell to apply changes. Malformed entries are silently
ignored and fall back to defaults.

## Windows Terminal Tabs

Jitzu reports the current working directory to Windows Terminal using its supported
`OSC 9;9` integration sequence. It also sets the tab title with the standard `OSC 2`
sequence so the active tab can identify the current directory.

Windows Terminal does not support dynamically changing the active tab color through
ANSI or OSC escape sequences. Jitzu therefore does not emit iTerm2-only tab color
sequences such as `OSC 6`, because Windows Terminal would ignore them.

For tab colors in Windows Terminal, use static profile or launch-time configuration:

<CodeBlock language="json" code={`{
  "profiles": {
    "defaults": {
      "tabColor": "#87af87"
    }
  }
}`} />

<CodeBlock language="shell" code={`wt new-tab --tabColor "#87af87"`} />

## Pagers

When `LESS` is unset, Jitzu sets it to `FR`. This lets Git's `less` pager use the
alternate screen, so resizing redraws the page without adding repeated text to
scrollback. Colors are preserved, and output that fits on one screen exits immediately.

An existing `LESS` value is preserved. To choose different options, set `LESS` before
starting Jitzu or add an `export LESS="..."` command to your startup configuration.

## Startup Configuration

The file `~/.jitzu/config.jz` is executed automatically when the shell starts,
similar to `.bashrc` or `.zshrc`.
Each line is run as a shell command, so you can set aliases, labels, environment variables,
and define Jitzu functions that will be available in every session.

<CodeBlock language="jitzu" code={`// ~/.jitzu/config.jz

// Set up aliases
alias ll="ls -la"
alias gs="git status"
alias gp="git push"

// Set up path labels
label git ~/git
label docs ~/Documents

// Set environment variables
export EDITOR=nvim
export DOTNET_CLI_TELEMETRY_OPTOUT=1

// Define helper functions
fun greet(): String {
    \`Good morning, {whoami}!\`
}`} />

Lines starting with `//` are treated as comments and skipped.

## Find Ignore Rules

`find` skips hidden entries and respects `.gitignore` rules in Git repositories,
repository `.git/info/exclude`, and `.ignore` and `.fdignore` files. Rules can
exclude files or directories, and nested ignore files and `!` negations are
supported. `.fdignore` takes precedence over `.ignore`, which takes precedence
over Git ignore rules.

To exclude generated folders, add patterns to your repository's `.gitignore`
or a `.fdignore` file in the directory you search:

<CodeBlock language="text" code={`node_modules/
bin/
obj/
release/
.cache/`} />

<CodeBlock language="shell" code={`find -F Float.Setup.exe
find -I -F Float.Setup.exe
find -HI
find -E '*.bak'`} />

`-H` includes hidden entries, `-I` bypasses ignore files, and `-HI` or `-u`
includes both hidden and ignored entries. `-E` excludes a glob for a single
search, even with `-I`. The previous `JITZU_FIND_IGNORE` environment setting
and `--include-ignored` option are replaced by ignore files and these flags.

## Aliases

Aliases map short names to longer commands. They persist to disk across sessions
and are automatically expanded when the alias name appears as the first word of a command.

<CodeBlock language="shell" code={`> alias ll="ls -la"
Alias set: ll → ls -la

> ll
d-----       -  Jan 15 09:44  src/
-a-r--   2.5K  Jan 15 14:23  Program.cs

> aliases
ll → ls -la
gs → git status

> unalias ll
Alias removed: ll`} />

Aliases are stored in the application data directory
(e.g. `~/.local/share/Jitzu/aliases.txt` on Linux
or `%APPDATA%/Jitzu/aliases.txt` on Windows).

## Path Labels

Labels map short names to directory paths. Use a label by appending a colon, e.g. `git:`.
Labels work in `cd`, file arguments, and tab completion.

<CodeBlock language="shell" code={`> label api ~/projects/api
Label set: api → /home/simon/projects/api

> cd api:
> pwd
/home/simon/projects/api

> cd api:src/controllers
> cat api:README.md

> labels
api → /home/simon/projects/api
docs → /home/simon/Documents

> unlabel api
Label removed: api`} />

Labels expand transparently in file arguments, so commands
like `cat api:src/Program.cs` and `ls api:` work
as expected. Tab completion also understands label prefixes.
